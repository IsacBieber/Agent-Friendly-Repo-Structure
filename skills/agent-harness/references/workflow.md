# 工作流

每个任务在当前项目的 `.agent-harness/<任务ID>/` 中保存记录。采用便于辨认的短任务 ID；重名时加数字后缀。只创建当前阶段需要的文件。

```text
.agent-harness/<任务ID>/
  1_input/raw.md
  3_runs/round_001/
    input.md
    work.md
    check.md
    evidence/
  4_review/round_001.md
```

## 冻结输入

- 把本任务的原始要求记在 `1_input/raw.md` 中，按 `## Input 001`、`## Input 002` 追加。在本轮 `input.md` 记录对应的输入编号、范围、必须保留的行为、关键假设和按 `R1`、`R2` 编号的验收条件。各项都写明怎样观察或验证。
- 开工后以本轮 `input.md` 为依据。需求实质变化时追加输入、创建新轮。此前的记录可用于解释变化和继续工作。

## 执行与验证

- 在项目原有位置完成工作。`work.md` 记录实际变化、候选路径或版本、下一步，阶段写为「进行中」或「待验证」。按上下文选择提交、差异、文件版本或其他可复核的候选身份。需要恢复时先核对当前候选与记录。
- 对实际候选逐条验证，在 `check.md` 中写明 `R` 编号、`通过 / 未通过 / 未验证 / 需人工决定`、证据和适用范围。只有需要保留原始文件或日志时才写入 `evidence/`。业务失败与验证器或环境故障分别记录。
- 稳定的自动验证用 [本地验证](verification.md)，先冻结验收条件和验证输入，再运行项目现有工具。换窗口引用结果前检查本轮回执和当前候选。候选、依赖或验收条件发生变化时重新验证。出现故障，先定位验证器、环境或业务问题再处理。
- 需要独立判断、改动影响较大或涉及人工判据时，用 [独立复核](independent-review.md) 交接。验证日志、差异和工作记录是待核证材料。没有独立评审通道时，验收页列出需要用户判断的项目。

## 人工验收

- 在 `4_review/round_NNN.md` 先写待人工决定和未验证项，再写实际变化、逐项结论和证据位置。验收页提交后如发生实质变化，开下一轮。完整日志留在相应证据文件。

## 恢复与查状态

- 从最新轮的 `input.md`、`work.md` 和已生成的验收页开始。输入编号或来源需要确认时，再读 `raw.md` 对应条目；验证需要补充时，再读 `check.md`、回执摘要和相关原始证据。输入已变更就进入新轮。缺 `input.md` 时补齐验收条件；缺 `work.md` 或阶段为「进行中」时接着做；阶段为「待验证」且缺有效 `check.md` 时进行验证；有检查结论但缺验收页时补写。已有有效验收页时返回对应结果。
- 同一任务跨设备续跑需要在目标工作区也能读到任务文件与候选。仅查看状态时报告最近已记录的事实及下一步。

## 正式工作区

用户指定续接已有正式工作区时，读取该工作区自己的 `ENGINE.md`、`2_tools/README.md` 和本轮记录。以程序状态提示定位阶段，核对输入、候选和证据。使用经校验的发布入口，并遵循该工作区的审批协议。2.2.2 的 Review、证据复用与发布恢复有已知校验缺口，应据此判断哪些结论可交给人。
